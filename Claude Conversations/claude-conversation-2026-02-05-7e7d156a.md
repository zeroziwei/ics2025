## 章节定位

**PA2.1 是 PA2 的开篇章节**，标志着从热身练习（PA1）过渡到真正的系统编程。这一章通过一个简化的模型来讲解 CPU 的核心工作原理。

## YEMU vs NEMU 的关系

### YEMU（教学用简化模型）
- **4 个 8 位寄存器**
- **4 位 PC**（程序计数器）
- **16 字节内存**
- **4 种指令**（mov, add, load, store）

### NEMU（你要实现的真实模拟器）
- 支持完整的 ISA（x86/MIPS/RISC-V）
- 完整的寄存器组
- 大容量内存
- 几十到上百条指令

**YEMU 的作用**：它是一个"玩具模型"，让你在简单环境下理解 CPU 的本质工作流程，然后再去实现复杂的 NEMU。

## 核心概念：指令执行周期

这一章讲解的**四阶段循环**是整个 NEMU 的核心：

```
while (true) {
  1. IF (取指)：从内存读取指令，地址由 PC 指定
  2. ID (译码)：解析指令的操作码和操作数
  3. EX (执行)：执行具体操作（算术、访存等）
  4. 更新 PC：指向下一条指令
}
```

### 问题：直接看 NEMU 代码会怎样？

如果直接看 NEMU 的代码，你会被淹没在：

### 解决：先用 YEMU 建立心智模型

YEMU 让你在**最简环境**下理解：
- CPU 就是一个**状态机**
- 每条指令就是一次**状态转换**
- 程序执行就是**不断重复这个循环**

有了这个心智模型，再看 NEMU 时就能：
- 忽略复杂的细节
- 抓住核心逻辑
- 知道自己在实现什么

## 🔧 INSTPAT 模式匹配机制详解

### 模式匹配的工作原理

从刚才读取的代码可以看到，`pattern_decode` 函数将模式字符串转换为三个关键变量：

```c
// 以 RISC-V 的 auipc 指令为例
INSTPAT("??????? ????? ????? ??? ????? 00101 11", auipc, U, R(rd) = s->pc + imm);

// 模式字符串解析后：
// key   = 0x17  (二进制: 0010111)
// mask  = 0x7f  (二进制: 1111111) - 只检查最低7位
// shift = 0     (opcode 从最低位开始)
```

**匹配过程**：
```c
if ((((uint64_t)s->isa.inst >> shift) & mask) == key) {
    // 匹配成功，执行指令
}
```

### 2️⃣ **RISC-V 指令格式完整图解**

RISC-V 有 **6 种基本指令格式**：

```
R-type: 寄存器-寄存器运算（add, sub, and, or, xor, sll, srl, sra, slt, sltu）
31      25 24   20 19   15 14  12 11    7 6      0
┌─────────┬───────┬───────┬──────┬───────┬────────┐
│ funct7  │  rs2  │  rs1  │funct3│   rd  │ opcode │
└─────────┴───────┴───────┴──────┴───────┴────────┘
例如: add rd, rs1, rs2  →  rd = rs1 + rs2

I-type: 立即数运算/加载（addi, slti, andi, ori, xori, lw, lh, lb, lbu, lhu）
31        20 19   15 14  12 11    7 6      0
┌───────────┬───────┬──────┬───────┬────────┐
│  imm[11:0]│  rs1  │funct3│   rd  │ opcode │
└───────────┴───────┴──────┴───────┴────────┘
例如: addi rd, rs1, imm  →  rd = rs1 + imm

S-type: 存储指令（sw, sh, sb）
31      25 24   20 19   15 14  12 11    7 6      0
┌─────────┬───────┬───────┬──────┬───────┬────────┐
│imm[11:5]│  rs2  │  rs1  │funct3│imm[4:0]│ opcode │
└─────────┴───────┴───────┴──────┴───────┴────────┘
例如: sw rs2, imm(rs1)  →  Mem[rs1 + imm] = rs2

B-type: 分支指令（beq, bne, blt, bge, bltu, bgeu）
31   30      25 24   20 19   15 14  12 11   8 7   6      0
┌──┬─────────┬───────┬───────┬──────┬──────┬──┬────────┐
│imm│imm[10:5]│  rs2  │  rs1  │funct3│imm[4:1]│imm│ opcode │
│[12]│         │       │      │        │[11]│        │
└──┴─────────┴───────┴───────┴──────┴──────┴──┴────────┘
例如: beq rs1, rs2, offset  →  if (rs1 == rs2) PC += offset

U-type: 大立即数（lui, auipc）
31        12 11    7 6      0
┌───────────┬───────┬────────┐
│  imm[31:12]│   rd  │ opcode │
└───────────┴───────┴────────┘
例如: lui rd, imm  →  rd = imm << 12

J-type: 跳转指令（jal）
31   30      21 20  19      12 11    7 6      0
┌──┬──────────┬──┬───────────┬───────┬────────┐
│imm│imm[10:1] │imm│ imm[19:12]│   rd  │ opcode │
│[20]│          │[11]│           │       │        │
└──┴──────────┴──┴───────────┴───────┴────────┘
例如: jal rd, offset  →  rd = PC + 4; PC += offset
```

### 5️⃣ **关键概念：snpc vs dnpc**

```c
// 在 decode_exec 开头
s->dnpc = s->snpc;  // 默认：下一条指令是顺序执行的

// 对于顺序执行的指令（如 add, addi）
// dnpc 保持不变，等于 snpc（PC + 4）

// 对于跳转指令（如 jal, beq）
// 需要修改 dnpc 指向跳转目标
s->dnpc = s->pc + offset;
```

**正确行为**：
- `si` 应该默认执行 1 条指令
- `si N` 应该执行 N 条指令
