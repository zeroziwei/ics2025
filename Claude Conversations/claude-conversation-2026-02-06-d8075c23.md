## 完整流程

### 第一步：初始化子项目

使用之前讲解的 `init.sh` 脚本初始化必要的子项目：

```bash
cd /mnt/c/Users/Omni/Documents/ics2025

# 初始化 NEMU（如果还没做）
bash init.sh nemu

# 初始化 Abstract Machine（如果还没做）
bash init.sh abstract-machine

# 初始化测试程序集
bash init.sh am-kernels
```

执行后需要让环境变量生效：
```bash
source ~/.bashrc
```

### 第二步：准备交叉编译环境

如果你选择的 ISA 不是 x86，需要安装交叉编译工具链：

```bash
# MIPS32
sudo apt-get install g++-mips-linux-gnu binutils-mips-linux-gnu

# RISC-V 32/64
sudo apt-get install g++-riscv64-linux-gnu binutils-riscv64-linux-gnu
```

### 第三步：配置 NEMU

在编译运行之前，必须先配置 NEMU：

```bash
cd nemu
make menuconfig  # 或使用预定义配置，如 make riscv32-am_defconfig
```

### 第四步：编译并运行第一个程序

目标程序是 `dummy.c`，它是最简单的测试程序（什么都不做就返回）：

```bash
cd am-kernels/tests/cpu-tests/
make ARCH=$ISA-nemu ALL=dummy run
```

将 `$ISA` 替换为你选择的架构，例如：
- `riscv32-nemu`
- `riscv64-nemu`
- `mips32-nemu`
- `x86-nemu`

### 第五步：处理"未实现指令"错误

首次运行会看到类似这样的错误：

```
invalid opcode(PC = 0x80000000):
        13 04 00 00 17 91 00 00 ...
        00000413 00009117...
```

这表示 NEMU 遇到了未实现的指令 `0x00000413`。

### 第六步：查看反汇编结果

查看程序需要哪些指令：

```bash
# 反汇编结果在这里
cat am-kernels/tests/cpu-tests/build/dummy-$ISA-nemu.txt
```

例如 RISC-V 32 的 dummy 程序可能包含：
- `addi` (加立即数)
- `auipc` (PC相对寻址)
- `jal` (跳转并链接)
- `ret` (返回，实际是 `jalr` 的伪指令)

### 第七步：实现指令

在 `nemu/src/isa/$ISA/inst.c` 中添加模式匹配规则。

以 RISC-V 的 `addi` 指令为例：

```c
INSTPAT("??????? ????? ????? 000 ????? 00100 11", addi, I, R(rd) = src1 + imm);
```

**关键步骤**：
1. **RTFM**：查阅 ISA 手册，了解指令的确切行为
2. **编写模式字符串**：根据指令编码格式
3. **指定指令类型**：如 I 型、R 型、U 型等
4. **实现执行逻辑**：用 C 代码模拟指令行为

### 第八步：重新编译 NEMU 并测试

```bash
cd nemu
make                                              # 编译 NEMU
cd ../am-kernels/tests/cpu-tests/
make ARCH=$ISA-nemu ALL=dummy run                 # 再次运行
```

重复第 6-8 步，直到实现所有需要的指令。

### 第九步：成功标志

当所有指令都正确实现后，你会看到：

```
HIT GOOD TRAP
```

这表示程序成功执行并正常退出。

## 工作原理

### 整个系统的协作关系

```
┌─────────────────┐
│   dummy.c       │  C 源代码
└────┬────────┘
         │ 交叉编译（gcc）
         ↓
┌─────────────────┐
│  dummy.elf      │  可执行文件（客户程序）
└────────┬────────┘
         │ 加载到内存
         ↓
┌─────────────────┐
│     NEMU        │  模拟器（执行指令）
│  ┌───────────┐  │
│  │ CPU 模拟  │  │  - 取指
│  │ 内存模拟  │  │  - 译码
│  │ 设备模拟  │  │  - 执行
│  └───────────┘  │  - 更新PC
└─────────────────┘
```

### Abstract Machine 的作用

`abstract-machine` 提供了：
- **启动代码**：初始化栈指针、跳转到 `main` 函数
- **运行时库**：提供 `putch`、`halt` 等基本功能
- **构建脚本**：生成能在 NEMU 中运行的程序镜像

这就是为什么需要用 `make ARCH=xxx-nemu` 来编译，而不是直接用 gcc。

## 调试技巧

如果遇到问题，可以：

1. **使用 GDB 调试 NEMU**：
   ```bash
   make ARCH=$ISA-nemu ALL=dummy gdb
   ```

2. **查看执行日志**：
   ```bash
   cat nemu/build/nemu-log.txt
   ```

3. **使用 NEMU 内置调试器（SDB）**：
   - `si N`：单步执行 N 条指令
   - `info r`：查看寄存器
   - `x N ADDR`：查看内存

4. **对比反汇编和执行流程**：
   - 反汇编文件显示静态指令序列
   - 日志文件显示动态执行轨迹

## 常见问题

1. **环境变量未生效**：记得 `source ~/.bashrc`
2. **交叉编译工具未安装**：按第二步安装
3. **NEMU 未配置**：必须先 `make menuconfig`
4. **指令实现错误**：务必 RTFM，不要想当然

这个过程体现了**自底向上构建计算机系统**的核心思想：从最基本的指令开始，逐步支持更复杂的程序运行。
