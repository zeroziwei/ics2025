解释“池”（pool）的概念和用途：

## 什么是"池"（Pool）？

池是一种内存管理技术：预先分配固定数量的对象，通过链表管理这些对象的分配与回收，避免频繁调用 `malloc()`/`free()`。

### 1. 池的结构

查看代码（第30-31行）：

```30:42:nemu/src/monitor/sdb/watchpoint.c
static WP wp_pool[NR_WP] = {};
static WP *head = NULL, *free_ = NULL;

void init_wp_pool() {
  int i;
  for (i = 0; i < NR_WP; i ++) {
    wp_pool[i].NO = i;
    wp_pool[i].next = (i == NR_WP - 1 ? NULL : &wp_pool[i + 1]);
  }

  head = NULL;
  free_ = wp_pool;
}
```

三个关键部分：
- `wp_pool[32]`：预分配的32个监视点结构体数组（池）
- `head`：指向正在使用的监视点链表头
- `free_`：指向空闲的监视点链表头

### 2. 为什么用池而不是 `malloc()`？

优势：
1. 性能：避免频繁分配/释放，减少系统调用开销
2. 确定性：预分配固定大小，避免内存碎片
3. 简单：无需处理分配失败（最多32个）
4. 适合嵌入式/模拟器场景：内存使用可预测

对比：
```c
// 使用 malloc() 的方式（不推荐）
WP *new_wp() {
    WP *wp = malloc(sizeof(WP));  // 每次都要系统调用
    if (wp == NULL) {              // 需要检查失败
        return NULL;
    }
    // ...
}

// 使用池的方式（推荐）
WP *new_wp() {
    WP *wp = free_;               // 直接从链表中取，O(1)
    free_ = free_->next;          // 无需系统调用
    // ...
}
```

### 3. 池的初始化过程

`init_wp_pool()` 做了什么？

```c
void init_wp_pool() {
  int i;
  // 1. 初始化每个监视点的编号
  for (i = 0; i < NR_WP; i ++) {
    wp_pool[i].NO = i;  // 编号：0, 1, 2, ..., 31
    
    // 2. 将32个监视点连接成链表
    wp_pool[i].next = (i == NR_WP - 1 ? NULL : &wp_pool[i + 1]);
    // 最后一个指向NULL，其他指向下一个
  }

  // 3. 初始化链表头
  head = NULL;        // 还没有使用的监视点
  free_ = wp_pool;    // 所有监视点都在空闲链表中
}
```

初始化后的状态：

```
wp_pool[0] → wp_pool[1] → wp_pool[2] → ... → wp_pool[31] → NULL
   ↑
  free_ (空闲链表头)

head = NULL (使用链表为空)
```

### 4. 两个链表的作用

- `free_` 链表：管理空闲的监视点
  - 创建监视点时从这里取
  - 删除监视点时放回这里

- `head` 链表：管理正在使用的监视点
  - 检查监视点时遍历这个链表
  - 删除时从这里移除

### 5. 完整工作流程示例

假设创建了2个监视点后的状态：

```
初始状态：
free_: wp_pool[0] → wp_pool[1] → ... → wp_pool[31] → NULL
head: NULL

创建第1个监视点 (w $pc):
free_: wp_pool[1] → wp_pool[2] → ... → wp_pool[31] → NULL
head: wp_pool[0] → NULL

创建第2个监视点 (w 0x80000000):
free_: wp_pool[2] → wp_pool[3] → ... → wp_pool[31] → NULL
head: wp_pool[1] → wp_pool[0] → NULL
```

### 6. 池的优缺点

优点：
- 快速：分配和释放都是 O(1)
- 无碎片：预分配，不会产生内存碎片
- 简单：无需处理分配失败
- 可预测：内存使用固定

缺点：
- 固定上限：最多32个监视点（可通过修改 `NR_WP` 调整）
- 内存占用：即使不用也占用内存（通常可接受）

### 7. 实际应用场景

这种池模式常见于：
- 嵌入式系统：资源受限，需要确定性
- 游戏引擎：对象池（子弹、粒子等）
- 网络编程：连接池
- 模拟器/调试器：资源管理需要可预测

## 总结

池是一种预分配的内存管理方式：
1. 预分配：启动时分配32个监视点
2. 链表管理：用两个链表分别管理空闲和使用的监视点
3. 快速分配：从空闲链表取，O(1) 时间复杂度
4. 快速回收：放回空闲链表，O(1) 时间复杂度

相比 `malloc()`，池在性能、确定性和实现简单性上更有优势，适合监视点这种数量有限、频繁创建/删除的场景。
