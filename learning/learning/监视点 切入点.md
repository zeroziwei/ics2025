### Q2: 监视点需要存储哪些信息？
**切入点：** 查看 `watchpoint.c` 第20-28行，看看 `WP` 结构体里有什么字段。

**观察：**
```c
typedef struct watchpoint {
  int NO;                    // 监视点的编号
  struct watchpoint *next;   // 指向下一个监视点的指针（链表）
  char expr[256];            // 要监视的表达式
  word_t old_val;            // 表达式的旧值
} WP;
```

**思考：**
- 为什么需要 `NO`？为什么需要 `next`？
- 为什么需要存储 `expr`（表达式）？
- 为什么需要存储 `old_val`（旧值）？新值在哪里计算？

**答案提示：**
- `NO`: 用户删除监视点时需要指定编号
- `next`: 可以同时设置多个监视点，用链表组织
- `expr`: 每次执行指令后需要重新计算表达式的值
- `old_val`: 用来和新值比较，判断是否发生变化

### Q7: 监视点什么时候被检查？

```c
static void execute(uint64_t n) {
  Decode s;
  for (;n > 0; n --) {
    exec_once(&s, cpu.pc);      // 执行一条指令
    g_nr_guest_inst ++;
    trace_and_difftest(&s, cpu.pc);
    
    // 检查监视点
    if (check_wp()) {            // 每执行完一条指令就检查
      nemu_state.state = NEMU_STOP;
      break;

  }
}
```

### Q10: 如何区分乘法和指针解引用？
**切入点：** 查看文档第47-64行的提示。

**问题：**
- 表达式 `2 * 3` 中的 `*` 是乘法

## 第五阶段：综合理解

### Q11: 完整的监视点工作流程是什么？
**综合问题：** 从用户输入命令到程序暂停，整个流程是什么？

**流程梳理：**
1. 用户在命令行输入：`w $pc`
2. `sdb_mainloop()` 解析命令，调用 `cmd_w("$pc")`
3. `cmd_w()` 调用 `new_wp("$pc")`
4. `new_wp()` 从 `free_` 链表获取一个监视点，存储表达式，计算初始值，加入 `head` 链表
5. 用户执行 `c` 或 `si`
6. `cpu_exec()` 调用 `execute()`
7. `execute()` 循环执行指令，每条指令后调用 `check_wp()`
8. `check_wp()` 遍历 `head` 链表，重新计算每个表达式的值
9. 如果值改变，输出信息，设置 `nemu_state.state = NEMU_STOP`
10. 程序暂停，返回到 `sdb_mainloop()`

**实践：**
- 在关键函数处添加 `printf()`，追踪整个流程
- 或者用GDB调试NEMU，观察函数调用栈
