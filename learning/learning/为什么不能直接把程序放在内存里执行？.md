
## 问题的答案

程序确实放在内存里执行，但还需要运行时环境提供基础设施。否则程序无法正确运行。

## 具体例子：看看程序执行需要什么

假设你写了一个最简单的C程序：

```c
// dummy.c
int main() {
    return 0;
}
```

如果只是把编译后的指令放在内存里，会发生什么？

### 问题1：CPU从哪里开始执行？

**如果没有运行时环境：**
- CPU不知道第一条指令在哪里
- 程序入口点是什么？`main()` 函数吗？不对，C程序不是从 `main()` 开始的

**运行时环境提供的：**
```asm
# start.S - 程序真正的入口点
_start:
  mv s0, zero
  la sp, _stack_pointer    # 设置栈指针！
  call _trm_init           # 然后调用初始化函数
```

看链接脚本：
```ld
ENTRY(_start)    # 告诉链接器：程序从这里开始！
```

### 问题2：程序需要栈（Stack）

**如果没有运行时环境：**
- 函数调用需要栈，但栈在哪里？
- 调用 `main()` 需要栈，但栈指针（`sp`）没有被设置

**运行时环境提供的：**
```asm
la sp, _stack_pointer    # 设置栈指针到正确的位置
```

链接脚本定义了栈的位置：
```ld
_stack_pointer = .;      # 栈指针的位置
```

### 问题3：程序如何结束？

**如果没有运行时环境：**
- `main()` 返回后，程序做什么？
- 返回码如何传递给NEMU？

**运行时环境提供的：**
```c
// trm.c
void _trm_init() {
  int ret = main(mainargs);    // 调用你的main函数
  halt(ret);                    // 程序结束时调用halt()
}
```

`halt()` 的实现：
```c
void halt(int code) {
  nemu_trap(code);    // 通过特殊指令告诉NEMU程序结束了
}
```

### 问题4：内存布局是什么？

**如果没有运行时环境：**
- `.text`、`.data`、`.bss` 放在哪里？
- 堆（heap）在哪里？

**运行时环境提供的：**
链接脚本定义了完整的内存布局：
```ld
SECTIONS {
  .text : { ... }      # 代码段
  .data : { ... }      # 数据段
  .bss : { ... }       # 未初始化数据
  _stack_pointer = .;  # 栈的位置
  _heap_start = ...;   # 堆的起始位置
}
```

### 问题5：全局变量初始化？

即使是 `dummy.c` 这样的简单程序，也可能需要：
- 初始化 `.bss` 段（全局变量初始化为0）
- 设置 `.data` 段（已初始化的全局变量）

这些都需要在程序开始前完成。

## 总结：执行流程对比

### ❌ 如果没有运行时环境：
```
CPU启动 → ??? → 执行main() → ??? → 结束?
          ↑                ↑
        入口在哪？     如何结束？
```

### ✅ 有运行时环境（AM提供的）：
```
CPU启动 
  ↓
_start (start.S)          ← 明确的入口点
  ↓
设置栈指针(sp)            ← 栈准备好了
  ↓
_trm_init()               ← 初始化
  ↓
main()                    ← 你的程序
  ↓
halt()                    ← 正确结束
  ↓
NEMU识别结束状态
```

## 类比理解

把程序放在内存里，就像把一辆车放在路上：
- 程序在内存 = 车在路上 ✓
- 但还需要：
  - 明确起点（`_start`）
  - 燃料系统（栈）
  - 终点站（`halt()`）
  - 道路规则（内存布局）
  - 支持系统（堆、初始化）
