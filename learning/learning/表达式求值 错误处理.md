## 问题1：如果表达式是 `"(5 + 4"`（少一个右括号），什么时候应该报错？

### 答案：在 `expr()` 函数的全局检查阶段报错

看代码第397-415行：

```c
// 检查括号匹配
int paren_count = 0;
for (int i = 0; i < nr_token; i++) {
  if (tokens[i].type == '(') {
    paren_count++;
  } else if (tokens[i].type == ')') {
    paren_count--;
  }
  if (paren_count < 0) {
    *success = false;
    printf("Error: Unmatched parentheses\n");
    return 0;  // 立即返回，不继续求值
  }
}
if (paren_count != 0) {  // 检查：如果最后count不为0，说明括号不匹配
  *success = false;
  printf("Error: Unmatched parentheses\n");
  return 0;
}
```

### 详细追踪：`"(5 + 4"`

假设词法分析后的tokens数组：
```
[0] {type: '(', str: "("}
[1] {type: TK_NUM, str: "5"}
[2] {type: '+', str: "+"}
[3] {type: TK_NUM, str: "4"}
```

检查过程：
```
paren_count = 0

i=0: tokens[0] = '('
     paren_count++ → 1

i=1: tokens[1] = "5" (数字，跳过)

i=2: tokens[2] = "+" (运算符，跳过)

i=3: tokens[3] = "4" (数字，跳过)

循环结束

检查: paren_count != 0? 
      paren_count = 1 ≠ 0  ✓
      → 报错："Error: Unmatched parentheses"
      → return 0 (不继续求值)
```

### 为什么在这里检查？

1. 早期检查：在求值前发现错误，避免无效计算
2. 全局检查：一次遍历检查所有括号
3. 简单高效：只需一个计数器

### 其他括号错误情况

#### 情况1：多余的右括号 `"5 + 4)"`

```
tokens: [5, +, 4, )]

检查过程:
i=0: "5" → paren_count = 0
i=1: "+" → paren_count = 0
i=2: "4" → paren_count = 0
i=3: ")" → paren_count-- → -1
     paren_count < 0? 是！
     → 立即报错："Error: Unmatched parentheses"
```

#### 情况2：嵌套括号不匹配 `"(5 + (4 - 2)"`

```
tokens: [(, 5, +, (, 4, -, 2, )]

检查过程:
i=0: "(" → paren_count = 1
i=1: "5" → paren_count = 1
i=2: "+" → paren_count = 1
i=3: "(" → paren_count = 2
i=4: "4" → paren_count = 2
i=5: "-" → paren_count = 2
i=6: "2" → paren_count = 2
i=7: ")" → paren_count = 1
循环结束
paren_count = 1 ≠ 0
→ 报错："Error: Unmatched parentheses"
```

## 问题2：如果除数是0，应该在哪里处理？

### 答案：在 `eval()` 函数中进行除法运算时检查

看代码第353-359行：

```c
case '/':
  if (val2 == 0) {
    *success = false;
    printf("Error: Division by zero\n");
    return 0;
  }
  return val1 / val2;
```

### 为什么在这里处理？

1. 运行时检查：只有在实际计算时才检查
2. 精确位置：知道是哪个除法运算出错
3. 递归安全：每次递归调用都会检查

### 详细追踪：`"10 / 0"`

假设tokens数组：
```
[0] {type: TK_NUM, str: "10"}
[1] {type: '/', str: "/"}
[2] {type: TK_NUM, str: "0"}
```

求值过程：
```
eval(0, 2): "10 / 0"
├─ 找主运算符: / (位置1)
├─ 递归计算左边: eval(0, 0) → "10" → 10
└─ 递归计算右边: eval(2, 2) → "0" → 0
└─ 执行除法:
   val1 = 10
   val2 = 0
   val2 == 0? 是！
   → *success = false
   → printf("Error: Division by zero")
   → return 0
```

### 更复杂的例子：`"10 / (5 - 5)"`

```
tokens: [10, /, (, 5, -, 5, )]

求值过程:
eval(0, 6): "10 / (5 - 5)"
├─ 找主运算符: / (位置1)
├─ 递归计算左边: eval(0, 0) → "10" → 10
└─ 递归计算右边: eval(2, 6) → "(5 - 5)"
   └─ 被括号包围，去掉括号 → eval(3, 5) → "5 - 5"
      ├─ 找主运算符: - (位置4)
      ├─ 递归计算左边: eval(3, 3) → "5" → 5
      └─ 递归计算右边: eval(5, 5) → "5" → 5
      └─ 计算: 5 - 5 = 0
   → 返回 0
└─ 执行除法:
   val1 = 10
   val2 = 0  ← 来自括号内的计算结果
   val2 == 0? 是！
   → 报错："Error: Division by zero"
```

## 错误处理的层次结构

### 第一层：词法分析阶段（`make_token()`）

错误类型：
- 无法识别的token
- 缓冲区溢出

处理方式：
```c
if (i == NR_REGEX) {
  printf("no match at position %d\n%s\n%*.s^\n", position, e, position, "");
  return false;  // 词法分析失败
}
```

### 第二层：语法检查阶段（`expr()`）

错误类型：
- 括号不匹配
- 空表达式

处理方式：
```c
// 括号匹配检查（第397-415行）
if (paren_count != 0) {
  *success = false;
  printf("Error: Unmatched parentheses\n");
  return 0;
}

// 空表达式检查（第380-384行）
if (nr_token == 0) {
  *success = false;
  printf("Error: Empty expression\n");
  return 0;
}
```

### 第三层：求值阶段（`eval()`）

错误类型：
- 除零错误
- 无效的token类型
- 找不到主运算符

处理方式：
```c
// 除零检查（第353-359行）
case '/':
  if (val2 == 0) {
    *success = false;
    printf("Error: Division by zero\n");
    return 0;
  }

// 无效token检查（第314-318行）
else {
  *success = false;
  printf("Error: Expected a number...\n");
  return 0;
}

// 找不到主运算符（第330-340行）
if (op == -1) {
  *success = false;
  printf("Error: No main operator found\n");
  return 0;
}
```

## 错误传播机制

### 使用 `success` 指针传递错误状态

看代码第279行和第343-347行：

```c
static uint32_t eval(int p, int q, bool *success) {
  ...
  uint32_t val1 = eval(p, op - 1, success);
  if (!*success) return 0;  // 如果子表达式出错，立即返回
  
  uint32_t val2 = eval(op + 1, q, success);
  if (!*success) return 0;  // 如果子表达式出错，立即返回
  ...
}
```

机制：
1. 每个递归调用都检查 `*success`
2. 如果子表达式出错，立即返回，不继续计算
3. 错误会向上传播到顶层

### 例子：错误传播

```
表达式: "10 / (5 / 0)"

eval(0, 8): "10 / (5 / 0)"
├─ 递归计算右边: eval(2, 8) → "(5 / 0)"
   └─ 去掉括号 → eval(3, 7) → "5 / 0"
      ├─ 递归计算右边: eval(5, 7) → "0" → 0
      └─ 执行除法:
         val2 == 0? 是！
         → *success = false
         → return 0
   → *success = false (错误传播)
   → return 0 (不继续计算)
└─ 检查: !*success? 是！
   → return 0 (立即返回，不执行外层除法)
```

## 关键理解点总结

1. 括号错误：在 `expr()` 中全局检查
   - 早期发现，避免无效计算
   - 使用计数器检查匹配

2. 除零错误：在 `eval()` 中运行时检查
   - 实际计算时检查
   - 递归调用中也会检查

3. 错误传播：使用 `success` 指针
   - 子表达式出错时立即返回
   - 错误向上传播

4. 错误处理层次：
   ```
   词法分析 → 语法检查 → 求值计算
      ↓          ↓          ↓
    token错误  括号错误   除零错误
   ```
