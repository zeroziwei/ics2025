## 问题6：什么是"主运算符"？

### 核心概念

主运算符 = 最后计算的运算符（优先级最低的运算符）

### 对于 `"5 + 4 * 3"`，主运算符是 `+` 还是 `*`？

答案：主运算符是 `+`

原因：
1. 运算顺序：先算 `4 * 3 = 12`，再算 `5 + 12 = 17`
2. 最后一步是加法，所以 `+` 是主运算符
3. `*` 的优先级更高，会先计算，不是主运算符

### 为什么说"主运算符是最后计算的运算符"？

看代码第266-270行：
```c
// 选择优先级最低的（最后计算），如果优先级相同，选择最右边的
if (priority <= min_priority) {
  min_priority = priority;
  main_op = i;
}
```

优先级定义（第244-264行）：
```c
case '+':
case '-':
  priority = 2;  // 加减法优先级低
  break;
case '*':
case '/':
  priority = 3;  // 乘除法优先级高
  break;
```

逻辑：
- 优先级高的先算（如 `*`）
- 优先级低的后算（如 `+`）
- 最后算的那个就是主运算符

### 可视化理解

```
表达式: "5 + 4 * 3"

计算过程:
  第一步: 4 * 3 = 12  (乘法先算)
  第二步: 5 + 12 = 17 (加法后算，这是主运算符)

主运算符: + (因为它是最后一步)
```

## 问题7：为什么要递归？

### 核心思想：分而治之

递归 = 把大问题拆成小问题，直到小到可以直接解决

### 如果表达式是 `"(5 + 4) * 3"`，应该先算哪个部分？

答案：先算括号内的 `(5 + 4)`，再算 `9 * 3`

递归过程：
```
eval(0, 4)  // 整个表达式: "(5 + 4) * 3"
  ↓
发现被括号包围？不是（整体不是被括号包围）
  ↓
找主运算符: * (在位置3)
  ↓
分裂:
  左边: tokens[0..2] = "(5 + 4)"
  右边: tokens[4] = "3"
  ↓
递归计算左边: eval(0, 2) → 先去掉括号 → eval(1, 1) → 返回9
递归计算右边: eval(4, 4) → 返回3
  ↓
最终: 9 * 3 = 27
```

### 如何把一个大问题拆成小问题？

看代码第343-347行：
```c
uint32_t val1 = eval(p, op - 1, success);  // 递归求左子表达式
if (!*success) return 0;

uint32_t val2 = eval(op + 1, q, success);  // 递归求右子表达式
if (!*success) return 0;
```

策略：
1. 找到主运算符，把表达式分成两部分
2. 递归计算左边
3. 递归计算右边
4. 用主运算符合并结果

### 递归的终止条件

看代码第286-318行：
```c
else if (p == q) {
  /* Single token.
   * 单个token，直接返回数值
   */
  if (tokens[p].type == TK_NUM) {
    uint32_t num;
    sscanf(tokens[p].str, "%u", &num);
    return num;  // 基础情况：直接返回
  }
  ...
}
```

当 `p == q` 时，只剩一个token（通常是数字），直接返回，不再递归。

## 问题8：括号的作用

### `check_parentheses()` 如何判断 `"(5 + 4)"` 是被括号包围的？

看代码第189-217行：

```c
static bool check_parentheses(int p, int q) {
  // 首先检查最外层是否是括号
  if (tokens[p].type != '(' || tokens[q].type != ')') {
    return false;
  }
  
  // 检查括号是否匹配
  int count = 0;
  for (int i = p; i <= q; i++) {
    if (tokens[i].type == '(') {
      count++;
    } else if (tokens[i].type == ')') {
      count--;
    }
    
    // 如果在中间位置count变为0，说明最外层括号不是包围整个表达式的
    if (count == 0 && i < q) {
      return false;
    }
  }
  
  return count == 0;
}
```

判断逻辑：
1. 最左边必须是 `(`
2. 最右边必须是 `)`
3. 括号必须匹配（count最终为0）
4. 中间不能提前匹配完（如果中间count变成0，说明括号没有包围整个表达式）

例子：`"(5 + 4)"`
```
p=0: '('  count=1
p=1: '5'  count=1
p=2: '+'  count=1
p=3: ' '  count=1
p=4: '4'  count=1
p=5: ')'  count=0  (在最后位置，匹配成功！)
→ 返回 true
```

### 为什么 `"(5 + 4) * 3"` 整体不算被括号包围？

因为最外层不是括号：
```
tokens[0] = '('
tokens[5] = ')'  ← 这是内层括号的右括号
tokens[6] = '*'
tokens[8] = '3'  ← 最右边不是 ')'
```

检查过程：
```
p=0: '('  ✓
q=8: '3'  ✗ (不是 ')')
→ 返回 false
```

即使最左边是 `(`，最右边不是 `)`，所以不算被括号包围。

## 问题9：实践题 - 手动追踪递归过程

### 对于表达式 `"4 + 3 * (2 - 1)"`，递归调用过程是怎样的？

假设词法分析后的tokens数组：
```
[0] {type: TK_NUM, str: "4"}
[1] {type: '+', str: "+"}
[2] {type: TK_NUM, str: "3"}
[3] {type: '*', str: "*"}
[4] {type: '(', str: "("}
[5] {type: TK_NUM, str: "2"}
[6] {type: '-', str: "-"}
[7] {type: TK_NUM, str: "1"}
[8] {type: ')', str: ")"}
```

### 详细递归调用过程：

```
第1层: eval(0, 8)  // 整个表达式: "4 + 3 * (2 - 1)"
  ├─ 检查: p==q? 否 (0 != 8)
  ├─ 检查: 被括号包围? 否 (tokens[0]不是'(')
  ├─ 找主运算符: 
  │   扫描tokens[0..8]:
  │     tokens[1] = '+' (优先级2, 不在括号内) ← 主运算符
  │     tokens[3] = '*' (优先级3, 在括号内，跳过)
  │     tokens[6] = '-' (优先级2, 在括号内，跳过)
  │   主运算符位置: op = 1
  │
  ├─ 递归计算左边: eval(0, 0)  // "4"
  │   └─ p==q: 是
  │   └─ 返回: 4
  │
  └─ 递归计算右边: eval(2, 8)  // "3 * (2 - 1)"
      ├─ 检查: p==q? 否 (2 != 8)
      ├─ 检查: 被括号包围? 否 (tokens[2]不是'(')
      ├─ 找主运算符:
      │   扫描tokens[2..8]:
      │     tokens[3] = '*' (优先级3, 不在括号内) ← 主运算符
      │     tokens[6] = '-' (优先级2, 在括号内，跳过)
      │   主运算符位置: op = 3
      │
      ├─ 递归计算左边: eval(2, 2)  // "3"
      │   └─ p==q: 是
      │   └─ 返回: 3
      │
      └─ 递归计算右边: eval(4, 8)  // "(2 - 1)"
          ├─ 检查: p==q? 否 (4 != 8)
          ├─ 检查: 被括号包围? 是！
          │   tokens[4] = '(' ✓
          │   tokens[8] = ')' ✓
          │   括号匹配检查: 通过 ✓
          │
          └─ 去掉括号，递归: eval(5, 7)  // "2 - 1"
              ├─ 检查: p==q? 否 (5 != 7)
              ├─ 检查: 被括号包围? 否
              ├─ 找主运算符:
              │   扫描tokens[5..7]:
              │     tokens[6] = '-' (优先级2) ← 主运算符
              │   主运算符位置: op = 6
              │
              ├─ 递归计算左边: eval(5, 5)  // "2"
              │   └─ p==q: 是
              │   └─ 返回: 2
              │
              └─ 递归计算右边: eval(7, 7)  // "1"
                  └─ p==q: 是
                  └─ 返回: 1
              └─ 计算: 2 - 1 = 1
          └─ 返回: 1
      └─ 计算: 3 * 1 = 3
  └─ 计算: 4 + 3 = 7

最终结果: 7
```

### 每次递归调用时，p和q的值：

```
eval(0, 8)   → 主运算符在1，分裂为:
  eval(0, 0)   → 返回 4
  eval(2, 8)   → 主运算符在3，分裂为:
    eval(2, 2)   → 返回 3
    eval(4, 8)   → 被括号包围，去掉括号:
      eval(5, 7)   → 主运算符在6，分裂为:
        eval(5, 5)   → 返回 2
        eval(7, 7)   → 返回 1
      → 返回 2-1=1
    → 返回 3*1=3
  → 返回 4+3=7
```

### 可视化调用树：

```
eval(0,8): "4 + 3 * (2 - 1)"
├─ 主运算符: + (位置1)
├─ 左边 eval(0,0): "4" → 4
└─ 右边 eval(2,8): "3 * (2 - 1)"
   ├─ 主运算符: * (位置3)
   ├─ 左边 eval(2,2): "3" → 3
   └─ 右边 eval(4,8): "(2 - 1)"
      └─ 去掉括号 → eval(5,7): "2 - 1"
         ├─ 主运算符: - (位置6)
         ├─ 左边 eval(5,5): "2" → 2
         └─ 右边 eval(7,7): "1" → 1
         → 2 - 1 = 1
      → 3 * 1 = 3
   → 4 + 3 = 7
```

## 关键理解点总结

1. 主运算符 = 优先级最低的运算符（最后计算）
   - `+` 和 `-` 优先级低（2）
   - `*` 和 `/` 优先级高（3）
   - 括号内的运算符不考虑

2. 递归 = 分而治之
   - 找到主运算符，分裂成两个子表达式
   - 递归计算左右两边
   - 基础情况：单个数字直接返回

3. 括号处理
   - 如果整个表达式被括号包围，去掉括号再递归
   - 括号内的运算符不参与主运算符的寻找

4. 递归终止
   - 当 `p == q` 时，只剩一个token（数字），直接返回

tokens: [10, -, 5, *, 2]

│

└─ 右边: eval(2,4) → "5 * 2"
   ├─ 主运算符: * (位置3)
