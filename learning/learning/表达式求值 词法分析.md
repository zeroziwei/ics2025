
## 问题3：Token是什么？

### 类比：把句子拆成单词

想象你在读英文句子：
```
"I love programming"
```

你会把它拆成：
- "I"（一个词）
- "love"（一个词）
- "programming"（一个词）

Token 就是表达式中的“词”。

### 对于 `"5 + 4"`，应该识别出几个token？

答案：3个token（空格不算）

```
字符串: "5 + 4"
        ↓
tokens数组:
  [0] {type: TK_NUM, str: "5"}
  [1] {type: '+', str: "+"}
  [2] {type: TK_NUM, str: "4"}
```

### 空格算token吗？为什么？

空格不算有效token，但需要被识别并丢弃。

看代码第127-129行：
```c
case TK_NOTYPE:
  //跳过空格不记录
  break;
```

原因：
1. 空格不影响计算：`"5+4"` 和 `"5 + 4"` 结果相同
2. 空格只是分隔符，帮助人类阅读
3. 识别后直接丢弃，不存入tokens数组

类比：读文章时，你会忽略多余的空格，只关注有意义的词。

## 问题4：正则表达式的作用

### 什么是正则表达式？

正则表达式是描述字符串模式的工具，用于匹配特定格式的文本。

### 如何用正则匹配一个数字？

看代码第55行：
```c
{"[0-9]+", TK_NUM},     // decimal number
```

解释：
- `[0-9]`：匹配0-9的任意一个数字
- `+`：表示“一个或多个”
- `[0-9]+`：匹配一个或多个连续数字

例子：
- `"123"` → 匹配（3个数字）
- `"456"` → 匹配（3个数字）
- `"0"` → 匹配（1个数字）
- `"abc"` → 不匹配（不是数字）

### 如何用正则匹配一个运算符，比如 `"+"`？

看代码第48行：
```c
{"\\+", '+'},         // plus
```

解释：
- `+` 在正则中是特殊字符（表示“一个或多个”）
- 要用 `\\+` 来匹配字面的 `+`
- 第一个 `\` 是C字符串转义，第二个 `\` 是正则转义

为什么需要两个反斜杠？
```c
// C语言字符串中，\\ 表示一个反斜杠字符
"\\+"  →  实际存储的是: \+  →  正则表达式看到的是: +
```

### 其他正则表达式例子

看代码中的规则：

```c
{" +", TK_NOTYPE},              // 空格：一个或多个空格
{"0x[0-9a-fA-F]+", TK_HEX},    // 十六进制：0x开头，后面是0-9或a-f或A-F
{"\\$[a-zA-Z0-9_]+", TK_REG}, // 寄存器：$开头，后面是字母数字下划线
{"\\(", '('},                  // 左括号：需要转义
```

## 问题5：实践题

### 对于字符串 `"12 + 34"`，识别后tokens数组应该是什么样子？

让我们手动追踪 `make_token()` 的执行过程：

```
输入: "12 + 34"
position = 0
```

步骤1：position=0，匹配 "12"
- 尝试规则 `[0-9]+` → 匹配成功！匹配到 "12"
- 存入 tokens[0] = {type: TK_NUM, str: "12"}
- position 移动到 2

步骤2：position=2，匹配空格
- 尝试规则 ` +` → 匹配成功！匹配到 " "
- 类型是 TK_NOTYPE，不存入tokens，直接跳过
- position 移动到 3

步骤3：position=3，匹配 "+"
- 尝试规则 `\\+` → 匹配成功！匹配到 "+"
- 存入 tokens[1] = {type: '+', str: "+"}
- position 移动到 4

步骤4：position=4，匹配空格
- 尝试规则 ` +` → 匹配成功！匹配到 " "
- 类型是 TK_NOTYPE，不存入tokens，直接跳过
- position 移动到 5

步骤5：position=5，匹配 "34"
- 尝试规则 `[0-9]+` → 匹配成功！匹配到 "34"
- 存入 tokens[2] = {type: TK_NUM, str: "34"}
- position 移动到 7

步骤6：position=7，遇到 '\0'，结束

最终结果：
```c
nr_token = 3
tokens[0] = {type: TK_NUM, str: "12"}
tokens[1] = {type: '+', str: "+"}
tokens[2] = {type: TK_NUM, str: "34"}
```

### 对于 `"12+34"`（无空格），还能正确识别吗？

能正确识别。

执行过程：

```
输入: "12+34"
position = 0
```

步骤1：position=0，匹配 "12"
- 规则 `[0-9]+` 匹配成功
- tokens[0] = {type: TK_NUM, str: "12"}
- position = 2

步骤2：position=2，匹配 "+"
- 规则 `\\+` 匹配成功
- tokens[1] = {type: '+', str: "+"}
- position = 3

步骤3：position=3，匹配 "34"
- 规则 `[0-9]+` 匹配成功
- tokens[2] = {type: TK_NUM, str: "34"}
- position = 5

最终结果：
```c
nr_token = 3
tokens[0] = {type: TK_NUM, str: "12"}
tokens[1] = {type: '+', str: "+"}
tokens[2] = {type: TK_NUM, str: "34"}
```

结论：有空格和没有空格，识别结果相同。空格只是被识别后丢弃，不影响token识别。

## 关键理解点总结

1. Token = 有意义的单元
   - 数字、运算符、括号都是token
   - 空格不是有效token（识别后丢弃）

2. 正则表达式 = 匹配模式
   - `[0-9]+` 匹配数字
   - `\\+` 匹配加号
   - 规则按顺序尝试，第一个匹配的生效

3. 识别过程 = 从左到右扫描
   - 每次匹配成功后，position向前移动
   - 空格被识别但不存储
   - 最终得到结构化的tokens数组

## 一个完整的例子

让我们看一个更复杂的例子：`"5 + 4 * 3"`

```
输入: "5 + 4 * 3"

识别过程:
position=0: 匹配 "5"   → tokens[0] = {TK_NUM, "5"}
position=1: 匹配 " "   → 跳过（TK_NOTYPE）
position=2: 匹配 "+"   → tokens[1] = {'+', "+"}
position=3: 匹配 " "   → 跳过
position=4: 匹配 "4"   → tokens[2] = {TK_NUM, "4"}
position=5: 匹配 " "   → 跳过
position=6: 匹配 "*"   → tokens[3] = {'*', "*"}
position=7: 匹配 " "   → 跳过
position=8: 匹配 "3"   → tokens[4] = {TK_NUM, "3"}

最终tokens数组:
[0] {type: TK_NUM, str: "5"}
[1] {type: '+', str: "+"}
[2] {type: TK_NUM, str: "4"}
[3] {type: '*', str: "*"}
[4] {type: TK_NUM, str: "3"}
```

这样，字符串就转换成了结构化的数据，可以进入下一步的递归求值了。
